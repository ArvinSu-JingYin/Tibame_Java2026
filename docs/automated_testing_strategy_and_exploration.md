# 每日記帳系統 (Daily Ledger System) - 自動化測試架構與探索報告

> **文件版本**：v1.0.0  
> **建立日期**：2026-09-02  
> **技術棧**：Java 21 / Spring Boot 3.3.3 / JUnit 5 / Mockito / H2 In-Memory DB / MS SQL Server

## 1. 探索背景與目標

本報告旨在針對 **每日記帳系統 (Daily Ledger System)** 規劃完整且可持續演進的自動化測試架構（Automated Testing Architecture）。涵蓋單元測試（Unit Test）、切片整合測試（Sliced Slice Test）、端到端測試（E2E Test）之技術選型、專案組織決策、現況覆蓋度盤點與後續實施路線圖。

---

## 2. 自動化測試分層架構 (Testing Pyramid)

本系統依據測試金字塔原則構建多層級測試體系，由底層快速、高頻率的單元測試，逐步往上構建切片測試與端到端業務流測試：

```
                    +-----------------------------+
                    |    E2E / UI 驗證測試        |  <-- 數量少 / 成本最高
                    |  (Playwright / Postman CLI) |      前後端完整整合驗證
                    +-----------------------------+
                    |       API 切片整合測試      |  <-- 數量中等 / 驗證端點
                    |    (@WebMvcTest + MockMvc)  |      驗證 Controller/DTO/Auth
                    +-----------------------------+
                    |      Repository 資料層測試  |  <-- 驗證 SQL / JPA 邏輯
                    |      (@DataJpaTest + H2)    |      Schema / 關聯 / 查詢
                    +-----------------------------+
                    |         單元測試            |  <-- 數量最多 / 速度最快 (毫秒級)
                    | (JUnit 5 + Mockito / AssertJ)|      業務邏輯 (Service / Crypto / 驗證)
                    +-----------------------------+
```

### 各測試層級職責說明

```
+---------------------------------------------------------------------------------+
| 1. 單元測試 (Unit Tests)                                                        |
+---------------------------------------------------------------------------------+
| • 目標：隔離外部依賴，純粹驗證 Service、加密演算、驗證邏輯與工具類別。               |
| • 工具：JUnit 5, Mockito (@Mock, @InjectMocks), AssertJ                         |
| • 執行速度：極快（毫秒級，無須啟動 Spring ApplicationContext）。                   |
+---------------------------------------------------------------------------------+

+---------------------------------------------------------------------------------+
| 2. Web API 切片測試 (Web Layer Slice Tests)                                     |
+---------------------------------------------------------------------------------+
| • 目標：測試 REST API 端點、URL 路由、HTTP 狀態碼、Bean Validation、JWT 攔截器。  |
| • 工具：@WebMvcTest, MockMvc, @MockBean                                         |
| • 特點：僅加載 Web 相關 Bean，Service 層使用 Mock 替代，兼顧速度與合約驗證。    |
+---------------------------------------------------------------------------------+

+---------------------------------------------------------------------------------+
| 3. 資料庫存取層測試 (Data Access Tests)                                         |
+---------------------------------------------------------------------------------+
| • 目標：驗證 Spring Data JPA Repository、自定義 JPQL 查詢與實體關聯。          |
| • 工具：@DataJpaTest, H2 In-Memory Database                                     |
| • 特點：驗證 SQL 語法與資料庫對映，測試結束後自動 Rollback。                    |
+---------------------------------------------------------------------------------+

+---------------------------------------------------------------------------------+
| 4. 業務全流程 E2E 測試 (End-to-End Flow Tests)                                  |
+---------------------------------------------------------------------------------+
| • 目標：跨 Controller -> Service -> Repository 完整端到端業務旅程。             |
| • 工具：@SpringBootTest(webEnvironment = RANDOM_PORT), TestRestTemplate        |
| • 介面層：可選用 Microsoft Playwright 進行瀏覽器 UI 自動化點擊與 Vue MVVM 驗證。|
+---------------------------------------------------------------------------------+
```

## 3. 專案組織決策：測試程式是否需拆分專案？

**決策結論：不需要拆分，強烈保持在同一專案的 `src/test/java` 內。**

### 架構決策分析 (ADR)

```
daily-ledger-system/
├── src/
│   ├── main/java/        <-- 生產環境業務程式碼 (Production Code)
│   │   └── com/tibame/...
│   │
│   └── test/java/        <-- 測試程式碼 (Test Code)
│       └── com/tibame/...
└── pom.xml
```

1. **打包自動隔離 (Zero Runtime Overhead)**：
   - 執行 `mvn package` 產出發布 JAR 時，Maven 會自動排除 `src/test` 內容，測試庫（JUnit、Mockito、H2 等）完全不會流入正式環境。
2. **即時連動重構 (Synchronized Refactoring)**：
   - 當修改 Service 方法簽名或欄位名稱時，IDE 與編譯器會即時在測試程式中提示錯誤並支援一鍵同步重構，杜絕程式碼與測試脫節 (Code Drift)。
3. **同 Package 可見性存取 (Package-Private Access)**：
   - 保持同 Package 宣告可直接測試套件內部的保護類別與方法，無須為了測試而破壞封裝將方法全開為 `public`。
4. **開發者體驗 (Developer Experience)**：
   - 本地開發者透過 `./mvnw test` 即可一鍵完成完整測試套件驗證。

## 4. 單元測試 (Unit Test) 最佳實踐準則

專案全面採用 **AAA (Arrange - Act - Assert) 模式** 與 **Mockito 隔離測試**：

```
+-----------------------------------------------------------------------------+
| 單元測試標準架構 (AAA Pattern)                                               |
+-----------------------------------------------------------------------------+
|                                                                             |
|  1. Arrange (準備階段)                                                      |
|     - 建立假資料 (Request DTO, Entity)。                                    |
|     - 使用 when(...).thenReturn(...) 定義 Mock Repository 行為。             |
|                                                                             |
|  2. Act (執行階段)                                                          |
|     - 呼叫待測 Service 業務方法。                                           |
|                                                                             |
|  3. Assert & Verify (斷言與驗證)                                            |
|     - assertNotNull(), assertEquals() 驗證回傳 VO 內容。                    |
|     - assertThrows() 驗證預期拋出的業務例外 (ApiException)。                 |
|     - verify(mockRepo, times(1)).save(...) 驗證相依元件被正確調用。         |
|                                                                             |
+-----------------------------------------------------------------------------+
```

## 5. 端到端測試 (E2E Test) 實施途徑

針對 E2E 測試，本專案評估以下兩大實施途徑：

```
+---------------------------------------------------------------------------------------+
| E2E 測試兩大路徑比較                                                                  |
+---------------------------------------------------------------------------------------+
|                                                                                       |
|   途徑 A：後端全流程 API E2E 測試 (Headless HTTP Flow)                                |
|   ------------------------------------------------                                   |
|   • 方式：使用 @SpringBootTest + TestRestTemplate / RestAssured                       |
|   • 特點：不需啟動真實瀏覽器，直接在 Java 內部以 HTTP 請求走完註冊 -> 登入 -> 記帳流程 |
|   • 存放位置：src/test/java/com/tibame/e2e/ApiFlowE2eTest.java                        |
|                                                                                       |
|   途徑 B：真實瀏覽器 UI E2E 測試 (Full Browser User Journey)                         |
|   ------------------------------------------------                                   |
|   • 方式：採用 Microsoft Playwright for Java                                          |
|   • 特點：模擬真實使用者在 Chromium 瀏覽器操作 Vue 3 雙向綁定、SweetAlert2 彈跳視窗   |
|   • 存放位置：src/test/java/com/tibame/e2e/UiJourneyE2eTest.java                      |
|                                                                                       |
+---------------------------------------------------------------------------------------+
```

## 7. 測試環境與資料隔離策略

```
+-----------------------------------------------------------------------------+
| 測試環境配置隔離                                                             |
+-----------------------------------------------------------------------------+
|                                                                             |
|   [src/main/resources/application.properties]                               |
|   • MS SQL Server (開發與生產環境真實資料庫)                                 |
|                                                                             |
|   [src/test/resources/application-test.properties]                          |
|   • H2 In-Memory Database (`jdbc:h2:mem:testdb;DB_CLOSE_DELAY=-1`)          |
|   • `spring.jpa.hibernate.ddl-auto=create-drop` (測試完畢即銷毀)             |
|                                                                             |
+-----------------------------------------------------------------------------+
```

1. **交易自動回滾**：整合測試使用 `@Transactional`，測試案例執行後自動 Rollback，不污染後續測試資料。
2. **零外部依賴**：測試環境預設使用 H2，確保在任何沒有安裝 MS SQL Server 的本機或 CI 機器上皆能獨立成功執行。

## 8. 自動化執行與 CI/CD 實施路線圖 (Roadmap)

```
[ 第一階段：補齊核心業務單元測試 (目標覆蓋率 70%) ]
  ├── 1. CategoryServiceTest  (分類建立、重名衝突校驗、查修刪、權限防護)
  └── 2. LedgerServiceTest    (收支記帳、金額正負數、分頁查詢、月度統計報表)
         │
         v
[ 第二階段：建立 Controller API 切片測試 (目標覆蓋率 85%) ]
  ├── 1. AuthApiControllerTest    (驗證註冊登入端點、DTO 格式檢驗、401/409 回應)
  └── 2. RecordApiControllerTest  (驗證 JWT Bearer 授權、記帳 CRUD、403 越權防護)
         │
         v
[ 第三階段：建立 API 跨模組 E2E 測試與 CI 自動化 ]
  ├── 1. LedgerFlowE2eTest        (以 @SpringBootTest 驗證完整業務使用者旅程)
  ├── 2. JaCoCo Maven Plugin      (設定 80% 覆蓋率門檻檢查)
  └── 3. GitHub Actions Pipeline  (每次 Push / PR 自動執行 `mvn test`)
```
